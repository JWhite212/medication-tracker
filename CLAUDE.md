# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Dev Commands

```bash
npm run dev          # Start dev server (port 5173)
npm run build        # Production build
npm run preview      # Preview production build
npx vitest run       # Run all unit tests
npx vitest run tests/unit/time.test.ts  # Run single test file

npx drizzle-kit push      # Push schema to Neon
```

## Architecture

Server-first SvelteKit app (Svelte 5 runes). Pages load via `+page.server.ts`, mutations via form actions with `use:enhance`. No client-side data fetching libraries.

- **`src/lib/server/`** — All database queries and server logic. Never imported from client code.
- **`src/lib/server/db/schema.ts`** — Single file for all Drizzle table definitions.
- **`src/lib/server/auth/lucia.ts`** — Lucia v3 session management. Sessions stored in DB, validated in `hooks.server.ts`.
- **`src/routes/(app)/`** — Authenticated route group. Auth guard in `+layout.server.ts` redirects to `/auth/login`.
- **`src/lib/components/`** — Svelte 5 components using `$props()`, `$state()`, `$derived()`, `$effect()` runes. No legacy `export let` syntax.
- **`src/lib/utils/validation.ts`** — All Zod schemas. Every form action validates input through these.

## Key Patterns

- All timestamps stored UTC (`timestamp with tz`), displayed in user's timezone via `Intl.DateTimeFormat`
- Live "time since" counters: client-side `$effect` + `setInterval(60s)` + `visibilitychange` recalc. No WebSocket.
- All DB queries scoped by `user_id` — never trust client-provided user context
- Audit log (`src/lib/server/audit.ts`) records all create/update/delete with JSONB diffs
- `updatePreferences` in `src/lib/server/preferences.ts` is the **only** audited write path for user preferences — it reads the before-image, writes, and logs the diff itself. Callers (the three settings form actions and the `/api/v1` `update_preferences` command) just call it; never re-hand-roll a `computeChanges` subset at a door, and never write `user_preferences` directly. The diff is scoped to `Object.keys(updates)` because `updatedAt` is rewritten on every save and a whole-row diff would log a change on a no-op.
- Inventory auto-decrements on dose log, auto-restores on delete
- Refill forecasting lives in `src/lib/server/inventory.ts` — single source of truth for daily-rate selection (schedules first, legacy columns next, 30-day history for PRN). Both `dashboard/+page.server.ts` and `medications/+page.server.ts` consume it. The same module owns severity classification (`critical ≤3d`, `warning ≤7d`, `watch ≤14d`).
- Analytics insights are deterministic — `buildInsights` in `src/lib/server/analytics.ts` is a pure function over already-computed stats. Add new rules by writing a small predicate that returns `Insight | null`; never inject prescriptive medical wording.
- **The expected-doses denominator has exactly one owner, split across two functions.** `expectedPerDayFor` in `analytics.ts` owns the rate (schedule rows first; the deprecated legacy column only for `scheduleType === "scheduled"`, or a PRN med gets a fabricated denominator), and `lifecycleEnd` in `analytics/lifecycle.ts` owns where the window closes. `getPerMedicationStats` and `getDailyAdherenceSeries` both consume them — they used to spell this quantity out independently and disagreed four ways, so the same page showed a falling adherence chart beside a healthy headline stat. Never re-derive either at a call site.
- **`archivedAt` is the stop signal, not `isArchived`, and not `endedAt`.** No UI writes `endedAt` — it arrives only via import or `/api/v1` — so archiving is the only "I stopped taking this" event a web user produces. Filtering analytics on the dateless `isArchived` flag erased what had been expected on every _past_ day too, so archiving retroactively improved your history; `lifecycleEnd` closes the window at the right instant instead. Read it through `lifecycleEnd`, never either column alone.
- **`src/lib/server/analytics/page-data.ts` owns the analytics page's composition.** `resolveAnalyticsQuery` turns the query string into the current and previous windows; `composeAnalyticsPageData` builds the payload from already-fetched results. `analytics/+page.server.ts` is I/O only — resolve, fetch, compose — so new derived values belong in the module, not back in the `load`. It sits beside `analytics/lifecycle.ts` rather than in `analytics.ts`, which is already 720 lines of queries plus pure helpers.

## Reusable Components

- **`Sparkline.svelte`** — inline-SVG line trend, no chart library. Pure path generation lives in `src/lib/utils/sparkline.ts:buildSparklineShape` so it's unit-testable. Used on Analytics stat cards (adherence + dose volume) and per-medication on the Medications list.
- **`EmptyState.svelte`** — standardised empty-state card. Props: `illustration`, `illustrationAlt`, `title`, `body`, `action` (`{ href?, label, onclick? }`). Used on Log and Medications; hold the line on consistency when wiring it into more pages.
- **`InsightsCard.svelte`** / **`StatusBreakdownBar.svelte`** / **`RefillsCard.svelte`** — analytics + dashboard surfaces; render nothing when their dataset is empty (don't wrap them in `{#if}` at the call site).

## Gotchas

- **Exactly one service worker.** SvelteKit builds `src/service-worker.ts` to `/service-worker.js` and registers it on every page automatically — `kit.serviceWorker.register` defaults to `true`. Never add a second script (e.g. `static/sw.js`) or a manual `navigator.serviceWorker.register(...)`: registrations are keyed by scope, so two scripts at `/` evict each other on every load. Push handlers, `pushsubscriptionchange` and offline caching all belong in that one file.
- Reminder delivery is driven by **two** schedulers hitting `/api/cron/reminders` with the same `CRON_SECRET` bearer: the Vercel cron (daily, Hobby plan cap) and the `reminder-tick` GitHub Actions schedule (every 30 min). `CRON_SECRET` must be set in the Vercel **production** env or the endpoint 500s before doing any work — that outage was silent for four months.
- **The dispatch send path is time-bounded, because the reminder loop is sequential.** `reminders.ts` awaits `withReminderClaim` once per medication in a `for` loop, and the whole tick shares one serverless function budget — so an unbounded send parks every _remaining_ medication, not just its own. `SEND_TIMEOUT_MS` (4s, in `reminders/dispatch.ts`) caps it, and a timeout lands in the same `catch` as a thrown provider error, which is why no extra handling was needed: unresolved intended channels are recorded `failed` and the row stays retryable, while a channel that already succeeded keeps its result and `deriveOverallStatus` resolves the row to `sent` — so a slow push after a delivered email does **not** cause the email to be sent twice. The limit worth knowing: `Promise.race` frees the loop, **not the socket**. A hung request keeps running in the background until the function exits; real cancellation would need an `AbortSignal` threaded into `resend` and `web-push`. The abandoned promise keeps a `.catch()` so a provider that fails long after we gave up cannot surface as an unhandled rejection.
- `computeOverdueSlot` for `fixed_time` scans back `OVERDUE_LOOKBACK_DAYS` (1) to find the most recent _elapsed_ slot. Evaluating only today's slot silently dropped every schedule timed after the cron tick — permanently, since the local date rolls over before the next tick. A dose at or after the slot satisfies it however late; the tolerance window only extends backwards.
- **`src/lib/utils/push-payload.ts` owns the push wire contract.** Senders build a `PushPayload` (all four fields required) and take their tag from the registry — `overdueTag`, `lowInventoryTag`, `TEST_PUSH_TAG` — never a hand-written string. The service worker reads via `toNotification` and `safeNotificationUrl`, so the fallback logic is unit-testable; the worker itself has no test attach point (jsdom has no `ServiceWorkerGlobalScope`). It lives in `utils/` and not `server/` because the worker imports it.
- Notification `tag`s are a replace-key: showing two notifications with the same tag leaves only the last one. That is why the registry's namespaces must stay disjoint (there is a test), why the test tag must never equal a reminder tag — sharing it would let "send test" silently clear a real reminder out of the tray — and why `toNotification` **omits** the tag for a payload that has none rather than substituting a shared default. A shared default would let two medications' notifications erase one another; untagged ones merely stack.
- **The push wire format is frozen.** Service workers update lazily, so a push can reach a device whose worker predates the deploy. Renaming or restructuring `title`/`body`/`url`/`tag` degrades silently for exactly the users who open the app least. Add fields, never rename them.
- A push the service accepts is not a push the user saw — the OS can suppress it after delivery. The service worker posts `TEST_PUSH_SHOWN_MESSAGE` back to open pages once `showNotification()` resolves for a test, which is the only signal available that it actually rendered. Only test pushes report back; real reminders stay silent.
- Drizzle `numeric` columns return as **string** in JS, not number. `medications.scheduleIntervalHours` and `dosageAmount` must be `Number(...)` before arithmetic.
- `medications.inventoryCount` is in **doses**, not raw units. `dose_logs.quantity` defaults to 1; inventory decrements by `quantity` per log, restores on delete.
- `scheduleType` / `scheduleIntervalHours` columns are marked DEPRECATED in `schema.ts` but still populated and read — the canonical source is the `medication_schedules` table (phase 4d).
- "Days until refill" prefers the schedule rate (`24/intervalHours`) over the 30-day historical average for `scheduleType === "scheduled"`. PRN meds use the historical average.
- **`tests/unit/helpers/fake-db.ts` owns the database seam for unit tests.** Tests mock `$lib/server/db` with `dbMock` and drive it through `fakeDb` — never a hand-rolled chainable. It dispatches on real table identity via drizzle's `getTableName`, so tests import the **real** schema and no test needs to mock `$lib/server/db/schema`. Writes land in two views: `attempted` is append-only (how far execution got before a throw), `committed` is rolled back when a `dbTx.transaction` callback throws (what a database would show afterwards) — `doses-inventory` asserts on the first, `createMedicationWithSchedules` on the second, and both are correct. `seedReturning` keeps `UPDATE ... RETURNING`'s after-image distinct from what a read sees, which is what `updatePreferences` diffs. `where` predicates are captured, never evaluated; assert on them with `predicateIncludes` (its circular-safe replacer is required — drizzle column nodes point back at their table, so a plain `JSON.stringify` throws). Modules that import `db` but run no query use `unusedDb`, which **throws** on access — do not "upgrade" those to `createFakeDb()`, because that turns a loud accidental query into a silent `[]`. `onConflictDoUpdate`'s config is captured as `RecordedCall.conflict` — for `claimReminderSlot` that upsert IS the dedupe mechanism, so it counts as part of a write's shape. **Exactly one file keeps a bespoke fake, on purpose and commented in place:** `reminders.test.ts` asserts on `whereArgsByCall[1]`, so table dispatch would delete that ordering assertion while leaving the suite green. `auth-totp.test.ts` used to be the second — its update _simulated the production WHERE clause_ — but that simulation is gone: the real compare-and-set now runs against PGlite in `tests/unit/pg/auth-totp.test.ts`, and the original file is on `unusedDb` because everything left in it is pure crypto. Anything else needing predicate evaluation belongs on `pg-db` (below), not in a bigger fake. CI runs with a placeholder `DATABASE_URL`.
- **`tests/unit/helpers/pg-db.ts` is the second backing, and choosing between the two is a rule, not a preference.** Use `fake-db` unless the behaviour under test is _decided by the database_ — either a predicate that gates whether a write happens at all (`checkRateLimit`'s `CASE` arms, `claimReminderSlot`'s `setWhere`, the TOTP compare-and-set), or SQL semantics a fixture cannot model (`jsonb_array_length` on `[]`, `ilike` escaping, `AT TIME ZONE` grouping). Everything else stays on the fake, which is far faster. PGlite files that exercise **production** code live in `tests/unit/pg/`; the helper's own test stays beside the helper as `tests/unit/helpers/pg-db.test.ts`, matching `fake-db.test.ts`. Wherever they live, they have three hard requirements: the `// @vitest-environment node` docblock (the suite default is jsdom, and PGlite takes a browser path when it sees `window`); `vi.useFakeTimers({ toFake: ["Date"] })` if a frozen clock is needed, because faking all timers stalls PGlite's WASM layer; and fixtures seeded via `pgDb.seedUser/seedMedication/seedDose` in that order, because real Postgres enforces the cascade foreign keys `fake-db` ignored. The helper applies the real `drizzle/` migrations, so those files are now tested too.
- `jsonb_array_length(...)` returns 0 for an empty array `[]` — not null. When filtering "with side effects" use `jsonb_array_length(coalesce(side_effects, '[]'::jsonb)) > 0` so both null and empty arrays are excluded.
- **A `LEFT JOIN` whose child predicates sit in the `WHERE` is an inner join wearing a disguise.** The null-extended rows fail the predicate and are discarded, so the parent rows you added the join for disappear again — and it still reads as correct. Child-side conditions belong in the `ON`; that is what `doseLogScope` in `analytics.ts` exists to return unjoined. Two related traps in the same query: `count(*)` counts an unmatched row as 1 (count the child key), and any per-row dispatch must have a branch for the null child.
- SQL `ilike` with user-provided text must escape `%` and `_` (and backslash) before wrapping in `%...%` — see `escapeLikePattern` in `src/routes/(app)/log/+page.server.ts`. Without escaping, a stray `%` in a search term matches everything.
- CSS percentage heights resolve against the parent's _defined_ height. Inside a `flex` container with `items-end`, child columns get content-driven height — so a `height: X%` bar inside collapses to 0. Fix: give the column wrapper `h-full` (or `h-32` etc.) and use `justify-end` on the column itself rather than `items-end` on the parent. See `analytics/+page.svelte` distribution charts for the pattern.
- **`src/lib/utils/schedule-rate.ts` owns the interval rate.** The same quantity lives in two places — `medication_schedules.intervalHours` and the parallel legacy column `medications.scheduleIntervalHours` — and every reader of either takes `parseIntervalHours` / `intervalDosesPerDay` from this module rather than spelling its own guard: `intervalHours` is a Drizzle `numeric` and arrives as a **string**, so `if (!intervalHours)` does not reject `"0"`. Six sites on the schedule-rows path wrote that guard differently and `computeOverdueSlot` got it wrong, reporting a medication overdue the instant it was logged; four more on the legacy-column path repeated it. `src/lib/utils/adherence.ts` shares the `parseIntervalHours` guard but deliberately keeps its own 1-per-day fallback instead of the primitive's 0 — don't "fix" that into `intervalDosesPerDay`. It lives in `utils/` and not `server/` because `utils/time.ts` and `utils/schedule.ts` are client-reachable.
- **`MAX_INTERVAL_HOURS` is a door policy, not a read policy.** Apply it in the two Zod schemas and the import gate only. A stored 168 (weekly injection) predates the bound and must still produce a rate — rejecting it on read would drop that medication out of refill forecasting, out of the adherence denominator and out of reminders. Apply it to the _parsed number_, never the raw string.
- **`medicationStatsFor`'s `legacyRate` is not a duplicate of `dailyRateFor`.** `expectedDailyDoses` is the adherence denominator and must be `null` when a medication has no scheduled rate; `dailyRateFor` always returns a number, falling back to `thirtyDayDoseCount / 30`. Substituting it would draw an adherence bar measuring a PRN user against their own past behaviour.
